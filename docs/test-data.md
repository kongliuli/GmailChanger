# 安全测试数据

优先使用 `tests/` 中的合成字符串，而不是提交真实导出。脱敏不是只删掉显示名：地址、标签、主题、Message-ID、路径和规则转发目标都可能识别个人。

## Gmail 过滤器 XML

1. 在 Gmail 设置 → 过滤器和被屏蔽的地址中，选择少量规则并导出；原件留在仓库外的私密目录。
2. 在离线编辑器中创建副本，保留 Atom/apps 命名空间及字段名称，地址替换成 `sender@example.com` / `recipient@example.org` 等保留示例域名。
3. 替换 entry id、时间、标题、label、subject、查询文本、转发目标与其他用户内容；不要因为某字段当前不支持就忽略其隐私风险。
4. 保留测试所需的结构（重复属性、错误命名空间等）而不是保留真实值；重新解析并检查预期转换状态。
5. 人工逐行复查，确认无个人数据，再放入 PR。Issue 中尽可能只贴最小合成样本。

## Takeout MBOX

1. 用 Google Takeout 导出少量专门用于测试的邮件，或直接照 `tests/mailbox.test.js` 合成 MBOX；不要提交完整邮箱。
2. 在仓库外解压。最好重新构造样本，仅保留合成 `From ` 信封行、`From:`、`Message-ID:`、`X-Gmail-Labels:` 以及测试必须的头字段。
3. 真实正文、HTML、签名、附件和 MIME base64 全部移除，以无个人含义的占位正文代替；将所有地址/ID/标签/文件名替换为合成值。
4. 若测试折行、CRLF、UTF-8、跨块边界或重复 ID，保留这些结构特征。重复用同一个合成 ID，不保留原 ID。
5. 复查压缩包内所有条目和元数据；仅把脱敏后最小文件加入测试。

## 绝不能提交

真实邮箱地址、真实邮件正文/附件、未脱敏过滤器导出、联系人、cookies、访问或刷新 tokens、密码、会话存储、私钥、账号后台截图。日志/截图/录屏同样要检查。不要依赖 `.gitignore` 代替脱敏；一旦误提交，应撤销凭证并联系维护者处理历史。

## 推荐样本矩阵

| 领域 | 最小覆盖 |
|---|---|
| XML | 正确命名空间、实体转义、重复/未知属性、DOCTYPE、损坏 XML、错误根节点 |
| 精确规则 | 单地址 from/to、大小三个单位/两个方向、label、flags、转发并保留本地副本 |
| 近似/拒绝 | subject、Archive/Trash、多规则交互、Gmail 查询、附件条件、非法地址/控制字符、冲突动作 |
| MBOX | Sent 与来信、中文标签、折叠头、引号标签、重复/缺失 ID、畸形头、超长行、空文件、取消 |
| 多文件 | Sent 与 All Mail 重叠、同一批次共享 `seen`、新批次/重置后不沿用、重复选择；100000 ID 上限。Worker 批次协议落地前标记为计划测试 |
| ZIP | 仅 XML/MBOX 的正常包、混入其他类型、ZIP64/损坏目录、512 MiB/128 MiB/256 MiB/2000 条目边界 |
| 输出/UI | 特殊字符转义、CSV 公式前缀、DOMParser、失败提示、近似默认禁用 |

大尺寸边界优先用可控生成数据/元数据测试，不把巨大归档提交到 Git。浏览器测试是 Chromium 测试，不代表 Firefox 或真实邮箱已验证。
