# 目标服务商与验证状态

选择目标不会登录邮箱、上传邮件、创建文件夹或启用规则。下面是转换器的能力，不是服务商认证；套餐和网页入口可能变化，以你自己的账号为准。

| target | 当前输出策略 | 兼容状态 | 手动检查 |
|---|---|---|---|
| `generic` | 核心语法 + fileinto；不允许 flags | 未验证：没有统一的服务端环境 | 是否支持 Sieve、fileinto、imap4flags，脚本语法和配额 |
| `fastmail` | 共享编译语法，候选允许 fileinto/imap4flags/redirect | **未验证真实账号** | Sieve 编辑能力、文件夹名称/层级、规则运行顺序、转发许可 |
| `proton` | 候选允许 fileinto/imap4flags，拒绝 redirect；保守采用 1 个活动脚本限制 | **未验证真实账号** | 当前套餐的 Sieve 能力与活动规则限制、标签/文件夹和标记语义 |
| `outlook` | 不生成可执行 Sieve，整条标为跳过 | 未验证；仅手动配方路线 | 网页规则可表达的条件、规则顺序、停止处理选项 |
| `yahoo` | 不生成可执行 Sieve，整条标为跳过 | 未验证；仅手动配方路线 | 网页筛选器支持的条件/动作及限制 |

**没有针对真实 Fastmail/Proton 账号测试，也没有兼容性保证。** 导出脚本中的“已转换”不是“已在服务端通过验证”。

## Sieve 手动检查清单

1. 备份目标邮箱现有规则；先使用测试文件夹和合成邮件。
2. 阅读 `gaps.md` 和 `rules.sieve`；近似规则整段注释，默认不运行。不要整体取消注释后直接投产。
3. 参考 `folders.json` 创建文件夹，核对分隔符、大小写、长度、Archive/Trash 是否为所需位置。
4. 确认 `fileinto` 和 `imap4flags` 可用；若手动启用近似规则，补齐对应 `require`。
5. 分别测试命中、不命中、交叉命中、多规则叠加、收件箱保留、归档、转发副本和已读/星标。
6. 确认没有额外副本或误归档后分批启用；发现异常立即禁用并恢复备份。
7. `senders.csv` 只是历史候选，不证明地址所有权或当前发信权限，必须逐个自行验证配置。

## Outlook / Yahoo：手动配方路径

在扩展中查看规则描述（条件 → 动作），结合“需人工检查”和下载的 `gaps.md`，逐条在服务商网页的规则/筛选器设置重建。`targets.js` 的 `buildRecipe` 可生成逐条原始条件/动作、手工步骤及注意事项；它是人读配方，不是导入文件或兼容性证明。必要时对照你本地原始 XML。

仅重建网页能准确表达的部分；表达不了的整条先停用并记录。用合成测试信核对后再启用。**不要导入 rules.sieve，也不生成或读取 Outlook `.rwz`。** 本项目不承诺提供各服务商当前菜单的深链或未验证的操作入口。
